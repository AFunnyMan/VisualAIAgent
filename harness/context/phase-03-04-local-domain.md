# 阶段 03/04 本地域层决策

日期：2026-09-07。范围：视觉记忆、事件状态机、关注任务，以及供 Agent/UI 共用的本地持久化接口。

## 事件与新鲜度

- `EventStateMachine` 只让 `running + fresh` 观察推进确认区间。非递增单调时间、超过 `max_gap_seconds` 的采样缺口，以及停止、暂停、断连、错误或过期状态都会重置待确认区间；已确认的出现事实不会因故障直接变成缺失。
- 出现需要三个连续有效样本。缺失只从已确认出现状态开始，并要求五秒连续有效未检测；事件使用单调钟判断持续时间，带时区墙钟只作事实记录。
- `MemoryStore` 重启后把数据库中的最后观察当作历史，不当作当前状态。当前新鲜度在查询时按墙钟动态计算；墙钟倒退也返回未知。采样档切换通过 `set_max_gap_seconds()` 更新阈值并重置确认区间。

## 存储边界

- 一个 `memory.sqlite3` 由 `MemoryStore` 管理，但视觉事实、关注与通知、完整对话轮次、Agent 用量和工具摘要使用独立表。Schema 版本当前为 2；版本 1 数据库会原位增加用量完整性字段，不删除历史运行。
- 截图先以临时文件落盘并原子改名，再与观察、事件和 `last_seen` 在事务中建立引用。数据库失败时不推进内存状态；不确定提交结果时保留可能的孤儿文件，后续清理处理，避免删除可能已被提交引用的证据。
- 普通观察和无通知引用的事件保留七天。`last_seen`、通知以及关注任务所引用的事件和证据受保护；清理同时移除崩溃残留的无索引文件。查询 Agent 的结果只返回证据 ID，文件路径仅由本地 UI 调用 `evidence_path()` 获取。
- 每次只让最新观察保有“当前截图”引用；历史事件和每类 `last_seen` 继续保护各自所需截图。该更新使用 `evidence_id IS NOT NULL` 的局部索引，避免随观察历史线性扫描全部行。

## 关注、恢复与额度

- 关注创建以 `request_id` 去重。事件匹配在 `BEGIN IMMEDIATE` 事务中把符合建立时间、期限、类别和条件的任务从 `waiting` 原子认领为 `processing`。
- `notify_user` 重新验证任务状态、事件事实、建立时间、期限和缺失事件的先前出现事实，并以 `(watch_id, event_id)` 唯一约束去重。取消和过期检查发生在写通知的事务内。
- `recover()` 核对已有通知并返回仍有效任务。调用方只需把带 `event_id` 的 `processing` 任务重新入队；`waiting` 任务继续等待未来事件，停机期间不补造事件。
- 自动事件运行以 `reserve_event_agent_run()` 在事务中预占日额度；`running` 和失败尝试均占额度。对话只保留最近五个完整用户/助手交互。提供商未返回的 Token 保持 `NULL`；日汇总只有在所有运行用量完整时才给出完整总数，同时用 `known_*` 字段保留失败前已收到的部分 Token，避免将部分用量误称为完整用量。
