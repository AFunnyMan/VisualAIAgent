# 2026-09-20 行为实时性能修复

用户授权实施并测试性能优化。现场原始姿态可高置信识别 seated，但同步保存与推理长尾超过 250ms，导致时间线重置与页面新鲜度保护。原始实测及限制见 [build-log](../build-log.md)。

本轮保持模型权重、置信阈值、250ms过期/连续性保护和事件定义。优先同帧分段耗时、SQLite WAL/FULL与切换前备份、相同契约预处理共享、有限线程实测。异步持久化仅在前述优化仍不能解决时另做严格顺序和故障设计，不先引入队列。

验证区分离线失败用例、历史数据库副本、真实USB联合运行和人工动作质量。持续测试使用R05＋杯复查＋姿态R04＋饮水R03；测试数据目录隔离，关闭Agent API调用，不保存完整视频。测试结束恢复原页面。真实动作无人工时间标记时只报告性能，不称饮水/离座准确率通过。Windows实机本轮不可用。

真实页面复验推翻了“独立Runtime通过即可收尾”的假设：独立10分钟稳定期99.95% fresh，但旧页面仍大量超时。线程栈命中Streamlit每次片段刷新强制全量GC和隐藏页历史统计。追加框架配置关闭每次重绘强制GC（保留自动GC）、当前标签按需构建、历史图片显式加载。只改GC的旧页面600秒仍未通过，保留失败记录。新页面必须分别核实实际720p/1080p，不能把驱动重启后实际输出尺寸变化当性能修复证据。最终结果以性能文档/汇总为准。
