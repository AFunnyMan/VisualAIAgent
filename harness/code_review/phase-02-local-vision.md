# 阶段 02 代码审查：本地低频视觉

审查日期：2026-09-07（Asia/Shanghai）

## 范围

审查 `visual_ai_agent/vision.py`、`scripts/prepare_model.py`、模型清单与 `tests/vision`。重点检查模型头格式、坐标还原、故障新鲜度、最新帧语义、线程停止、资源释放、同类多候选和运行时依赖隔离。

## 发现与处理

1. **已修复：参考推理预处理不一致。** 首次 PT 预测保留 Ultralytics 默认矩形批处理，而业务模型固定 640×640，造成最大 7.9 像素框差。两端统一 `rect=False` 后收紧公差，实测最大框差 0.000610 像素、最大置信度差 0.00000131。
2. **已修复：工作线程存活判断只观察采集线程。** 回放结束或打开失败后，推理线程仍可能存活，旧实现可能允许重复启动。`running` 现在检查两个线程，`stop` 也保持幂等。
3. **已修复：最近帧可能暂时遮盖摄像头断连。** 推理现在优先检查 disconnected/error/paused，并发布无效空观察；不会把断连后的旧像素当成新的有效采样。
4. **已修复：模型来源校验不足。** 检测器现在强制清单、配置和实际 SHA 一致，并核对静态输入输出形状、端到端标志及 COCO 类别元数据。测试替身只能显式跳过清单。
5. **已修复：慢推理可能把已过期帧发布成有效事实。** 旧实现只在调用 detector 前检查年龄；当推理本身超过 `stale_after` 时仍可能发布 `fresh=true`。现在 detector 完成后及绘制/JPEG 完成到发布前都会重新检查年龄、停止信号和源状态；过期结果为空检测、`fresh=false`，不会进入物品确认链路。
6. **已修复：阻塞读取会拖延停止并可能造成重复工作线程。** `stop()` 现在先设置停止信号并关闭 source，以解除 OpenCV/回放读取，再等待线程；若 source 忽略关闭且超时，发布可见错误并保留活线程句柄，`start()` 不会建立第二组线程。线程真正退出后可以再次停止清理并正常重启。
7. **已验证：EOF 和相同旧帧不重复推理。** 回放最后一个有效帧最多处理一次，之后相同序号只发布无效 stale 状态，不再次调用 detector，也不携带旧检测。
8. **已修复：ORT import-time telemetry 旁路文件。** 在导入原生 `onnxruntime` 前设置官方支持的 `ORT_DISABLE_TELEMETRY=1`；独立子进程回归确认没有警告或生成 `:memory:.ses`。Python API 的 `disable_telemetry_events()` 继续作为导入后的第二层关闭。

## 结论

离线实现范围未发现未处理的阻断问题。视觉定向测试共 22 项；本轮新增 7 项，分别覆盖慢推理过期、回放 EOF 后旧帧不重复推理、完整 stop/start、断连后缓存像素失效、关闭解除阻塞 read、无法解除 read 时停止超时且拒绝重复启动，以及 import 前禁用 ORT telemetry。此前用例继续覆盖输入校验、letterbox 往返与裁剪、三分区、端到端输出拒绝、哈希篡改、多同类候选、Supervision 绘制、摄像头打开失败/释放、最新帧丢弃和错误观察。真实摄像头、Windows 和长时间运行属于明确未执行的阶段验收，不计为通过。
