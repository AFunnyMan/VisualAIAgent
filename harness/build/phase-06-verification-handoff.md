# 阶段 06：双平台验证与交接

## 目的与前置条件

目标 G01—G08。交付可重复演示的源码版，并用证据说明实际能力与限制。阶段 00—05 的功能已实现；遗留的 API/摄像头/平台验证必须在此补齐或保留未完成。实际进度见 [build-log](../build-log.md)。

阅读 [完整验收矩阵](../../docs/testing.md)、[目标](../../GOALS.md)、[架构](../../docs/architecture.md)、全部阶段审查与相关 context。

## 范围与步骤

1. 核对依赖锁、模型来源/校验、配置样例和启动入口，分别准备 Mac/Windows 原生启动脚本；不制作安装包或发布站点。
2. 在可复现环境运行离线回归和静态检查，审查所有需求是否有测试/实机证据。
3. 用实际配置的文字模型验证查询、创建、取消和事件触发，记录工具调用及真实用量，不以模拟结果替代。
4. 在两类平台各做三十分钟运行和三类物品各十次放入/移出；记录误报、漏报、CPU、内存、推理和提醒延迟。
5. 验证断网、摄像头断开、应用重启、任务去重和截图清理；修复实质问题后有针对性复验。
6. 按实际结果更新 README 安装/配置/演示/故障排查、testing 平台矩阵、第三方版本许可和交接材料。
7. 完成一次项目复盘：把已验证问题转成适当回归测试或项目约定，记录保留限制；不自动扩展全局 Skill。

## 验证与完成条件

执行 testing 中已建立的统一命令及真实场景，记录当前代码版本、环境、退出状态和关键结果。所有需求都有对应证据；阶段审查无未处理的阻断问题；模型、数据与通知恢复行为符合约定。

Windows 实机或真实 API 条件缺失时，本阶段不能标为完成。交付可用部分与明确待验证项，说明需要的机器/配置，继续其他已授权检查。不能用 Linux 容器通过代替 Windows 原生摄像头通过。

## 恢复、提交与交接

验证用单独数据目录，不清理用户真实记录。重要可验证修复和最终源码交付分别形成 Git 提交；推送正常更新，不重写远程历史。记录最后检查、剩余事项与下一条操作。后续部署、发布或新增产品功能需要用户另行启动。
