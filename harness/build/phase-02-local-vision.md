# 阶段 02：本地低频视觉

## 目的与前置条件

目标 G01、G06。用户能看到三类物品的检测框、区域和摄像头状态。阶段 00 可运行，阶段 01 的离线服务边界明确；缺少真实模型 Key 不阻塞此阶段。实际进度见 [build-log](../build-log.md)。

阅读 [架构](../../docs/architecture.md)、[测试](../../docs/testing.md)、[模型来源](../../docs/references.md)。

## 范围与接口

实现 Camera/Replay 输入适配、Detection、SceneObservation 和 Detector。使用 OpenCV、ONNX Runtime 和 Supervision。首版无训练、姿态、身份跟踪、云端图像或 Docker USB 转发。

## 实施步骤

1. 先验证本机 USB 摄像头可打开、获取有效画面并释放；报告权限/占用/断开，记录真实分辨率及平台后端。
2. 从官方来源准备 YOLO26n，并在独立的开发导出环境生成 ONNX；记录版本、导出参数、类别和 SHA-256。学员运行不加载训练工具链。
3. 校验模型输出与预处理/后处理，比较参考推理与 ONNX 的类别、框和置信度，避免导出头格式误解。
4. 按架构实现低频推理、最新帧缓冲、两个 CPU 线程、有效时间戳、左右区域及无镜像显示。Supervision 仅作本地辅助。
5. 实现录像/模拟输入以支持无设备测试，记录 CPU、内存和推理耗时；明确摄像头断连与过期观察。

## 验证与验收

建立 tests/vision 中的预处理、坐标映射、新鲜度和输入异常用例；使用 `uv run pytest tests/vision -m "not live_api and not camera"`，实际目录建立后核验。

真实摄像头按 testing 中的设备步骤执行，确认手机、杯子和瓶子可检测、候选不伪装为身份、推理不积压帧、停止后设备可再次打开。各平台的安装和实机证据分别记录；Windows 未测不能写为已支持。

## 恢复与交接

摄像头缺失时运行回放检查，保留硬件验收为待执行。模型校验失败重新获取官方来源，不使用未知替代权重。记录导出格式、依赖版本和采集限制，交付阶段 03 的有效观察接口。运行截图与模型二进制不提交 Git。
