# 阶段 03：事件与视觉记忆

## 目的与前置条件

目标 G02。即使物品不再出现，也能查到最后有效观察和证据。阶段 02 能提供新鲜且带状态的观察。实际进度见 [build-log](../build-log.md)。

阅读 [事件和存储约定](../../docs/architecture.md)、[验收](../../docs/testing.md)。

## 范围与接口

实现 VisualEvent、事件状态机、SQLite 记忆仓储、截图引用与保留策略。连接 get_current_scene、find_object、search_events 的真实服务，替换阶段 01 的模拟数据。此阶段不接入自动 Agent 唤醒。

## 实施步骤

1. 为三次出现、五秒缺失、两秒遮挡、长采样缺口、区域边界和断连建立假时钟测试。
2. 以最小状态机实现有效采样确认；无图像不是未检测到，摄像头故障与重启空白时段不形成物品消失。
3. 建立有版本的数据库初始化和事务边界，存储最新观察、事件及证据索引；按类别/区域返回候选，不推测身份。
4. 建立截图写入与数据库引用协调，处理写图失败、数据库错误和残留文件；查询返回 last_seen 与证据状态。
5. 实现七天普通数据清理与最后观察证据保护，测试清理后引用完整。
6. 联接真实观察和 Agent 只读查询，重启验证持久化，记录现场效果。

## 验证与验收

建立 tests/memory 和 tests/events，计划执行 `uv run pytest tests/memory tests/events -m "not live_api and not camera"`。测试临时数据库，不修改真实用户数据。

通过条件：拿走手机后可查证最后位置与时间；两秒遮挡不误报；断连不伪造缺失；多个候选与未知类别回答准确；重启、磁盘错误和清理不造成伪造或悬空证据。手工演示记录与离线测试分开。

## 恢复与交接

数据库结构变更先备份已有数据，不以删除数据库修复错误。失败的截图写入不能冒充有效证据。记录事件语义和迁移方式，交付阶段 04 使用的唯一事件 ID。模拟服务只保留在显式测试/演示模式，不污染真实记忆。
