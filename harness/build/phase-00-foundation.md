# 阶段 00：建立可安装的开发基础

## 目的与前置条件

目标 G08。用户启动该阶段后，使新接手者可以安装开发环境并理解应用入口。当前已完成的文档/Git 准备是前置材料，不代表运行环境已经建立。实际进度见 [build-log](../build-log.md)。

阅读 [工作约定](../../AGENTS.md)、[目标](../../GOALS.md)、[架构](../../docs/architecture.md)、[测试](../../docs/testing.md)。只在用户主动授权后实施。

## 范围与接口

建立 Python 3.11 + uv 项目配置、dev 依赖、锁文件和不含秘密的配置样例，建立可被后续模块导入的包结构。应用入口计划为根目录 app.py，业务代码放在 visual_ai_agent 包中；此阶段不实现摄像头、检测、数据库、工具调用或 UI 功能。

## 实施步骤

1. 核对已有 Git、文档与工作树，不覆盖当前文档；只创建缺少的基础配置。
2. 验证 Python/uv 可用性及平台兼容依赖，创建隔离环境。把基础运行依赖与开发依赖分开，不安装语音、GPU 或训练扩展。
3. 建立 pyproject.toml、锁文件及配置加载约定，明确模型名称/API 地址/Key 的外部输入；无配置不访问网络。
4. 配置 Ruff、pytest 标记和默认离线测试约束。仅给实际配置行为建立必要用例，不用空测试伪装基础完成。
5. 用新的隔离环境验证锁定安装，更新 README 中已验证的准备步骤，审查并提交阶段里程碑。

## 验证与验收

拟建立并验证 `uv sync --locked --group dev`、`uv run ruff check .` 与默认离线测试入口。首次锁定需先生成 lock，再执行 locked 验证。测试命令见统一测试说明。

通过条件：环境可安装、关键依赖可导入、无 Key 不发生模型调用、默认测试不会访问摄像头、文档中的实际命令可复现。不能将安装完成宣称为产品功能完成。

## 恢复与记录

环境失败时保留错误并修复版本约束，只重建可再生虚拟环境，不删除用户数据。context 在阶段实际开始时创建，记录版本取舍和平台限制；结果归日志，审查归 code_review。本阶段结束后按照用户授权范围继续或停止。
