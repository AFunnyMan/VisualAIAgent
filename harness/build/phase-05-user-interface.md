# 阶段 05：完整本地操作界面

## 目的与前置条件

目标 G03、G04、G07。用户在一个页面完成观察、对话、历史查询和任务管理。阶段 01—04 的本地服务和错误返回已可调用。实际进度见 [build-log](../build-log.md)。

阅读 [架构](../../docs/architecture.md)、[目标](../../GOALS.md)、[测试](../../docs/testing.md)。

## 范围与接口

使用 Streamlit，计划入口为根目录 app.py。页面包括画面和状态、聊天、事件时间线、关注任务、证据与用量；只调用已有业务服务，不再实现一套独立的 GUI 业务逻辑。

## 实施步骤

1. 建立明确的采集启动/停止与摄像头选择入口，显示实际有效画面和断连/权限错误。
2. 采用局部刷新读取后台状态，防止 Streamlit 重运行重复建立摄像头、模型或工作队列。
3. 加入聊天和有限的工具执行记录，显示已执行动作与结果，不展示模型内部推理。无 Key 与模拟模式清楚标识。
4. 展示历史的最后观察时间、区域、截图和候选；过期数据不显示成当前事实。
5. 展示关注任务与一次性通知、取消结果、模型用量和限额；API 等待不阻塞画面。
6. 只监听本机；落实应用退出、资源释放和重新启动，更新已验证的使用说明。

## 验证与验收

建立必要的 UI/服务集成测试，执行适当离线回归。实际入口建立后运行 `uv run streamlit run app.py`，在本机浏览器按三类物品和 Agent 场景操作。

通过条件：完整“识别—查询—关注—提醒—取消”流程可操作；反复交互/刷新不增加工作实例；停止释放设备；未知、故障、历史和降级状态清晰；界面没有 Key 或不必要内部配置泄露。

## 恢复与交接

UI 重建从持久化服务恢复任务和历史，不重发已经投递通知。慢请求有明确等待和失败状态。页面视觉检查与逻辑测试分别记录，未执行的浏览器/实机验证不标通过；提交经验证的阶段成果。
