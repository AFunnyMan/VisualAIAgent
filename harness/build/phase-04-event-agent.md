# 阶段 04：关注任务与事件唤醒

## 目的与前置条件

目标 G04、G05。用户通过自然语言设定关注，等待期间不消耗模型请求，相关事件触发有证据的提醒。阶段 01 工具循环与阶段 03 事件/记忆可用。实际进度见 [build-log](../build-log.md)。

阅读 [任务状态、成本和工具约定](../../docs/architecture.md)、[验收](../../docs/testing.md)。

## 范围与接口

实现 WatchTask、持久化任务/通知、事件匹配、独立 Agent 工作队列和任务恢复。复用 create_watch、list_watches、cancel_watch、notify_user。没有匹配事件不得轮询模型。

## 实施步骤

1. 定义并测试等待/处理中/完成/取消/过期转换；默认三十分钟、一条成功提醒后结束。
2. 持久化任务建立及请求去重，任务只消费建立后的相关事实；缺失任务不能将从未见过当成消失。
3. 事件匹配后唤醒 Agent，提供任务/事件引用，由工具读取最新观察和证据；取消或过期时阻止迟到通知。
4. 用任务 ID + 事件 ID 去重通知，事务保证重复调用/并发处理不会写入两条有效提醒。
5. 加入每次三轮请求、每日二十次自动运行上限和实际用量记录，关闭自动重试。到限额或 API 失败时本地规则提醒明确标注降级，不记为 Agent 完成。
6. 实现重启恢复：核对处理中任务的已写通知，恢复有效等待任务，不补造停机事件、不重发过时通知。

## 验证与验收

建立 tests/watches 与对应 Agent 测试，计划执行 `uv run pytest tests/watches tests/agent -m "not live_api and not camera"`。以假时钟和受控模型验证边界、并发、限额和重复事件，再单独执行真实模型+摄像头场景。

通过条件：实际创建/取消；真实 Agent 复查并调用提醒工具；重复事件只有一条有效通知；无事件十分钟模型调用计数不增加；断连、取消、到期、失败与重启不误导用户。

## 恢复与交接

模型不可用时仍保存视觉事实，记录降级和未完成验证。取消在工具执行时再次检查，不能只靠模型提示。应用停止后可从任务/通知表恢复，不能通过清空表掩盖重复处理缺陷。交付阶段 05 的页面通知和任务状态接口。
