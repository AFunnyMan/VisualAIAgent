# 多条件情境提醒：固定场景扩展方案

2026-09-09，Asia/Shanghai。用户希望加入类似“钥匙在桌上、关闭电脑、超过18点时提醒带钥匙回家”的能力。本文是可实施方案，尚未创建真实规则、接入系统事件或修改生产模型。

## 用户体验与规则

通过自然语言建立规则，在页面显示结构化解释并允许修改、停用。用户已澄清“合上笔记本盖子，运行模型的电脑长期开机”。按被观察笔记本合盖、推理主机持续在线的部署方式设计，优先以视觉判断合盖，不等待主机关机事件。首条规则建议语义如下：

| 项目 | 示例 |
|---|---|
| 触发 | 指定笔记本从确认打开变为确认合盖，产生本次合盖事件 |
| 时间条件 | 触发时本地时间严格晚于18:00，时区Asia/Shanghai |
| 视觉条件 | 当前有效画面中，钥匙在配置的桌面区域得到稳定检测 |
| 动作 | 提醒“离开前记得带钥匙”，附最后确认时间与证据 |
| 去重 | 同一规则、同一次触发只产生一条有效通知 |

这是“合盖时检查条件”的建议，不等同于“任意条件变化后，只要三个状态都成立就提醒”。例如17:59合盖、18:01才超过时间，不自动重新解释成一次合盖；若要支持这种用法，应明确选择状态条件模式及有效时窗。过去某次合盖不能成为永久有效条件。

## 当前基础与真实缺口

- 可复用单摄像头、本地ONNX、SQLite事实与证据、关注任务、Agent队列、取消/过期/限额及通知去重。
- 当前业务类别只有杯、手机、瓶，关注条件只有appeared/missing。核验r03数据配置为COCO80，只有keyboard而没有钥匙类别；不能将现有模型输出或键盘类别当钥匙能力。
- 钥匙需要新增固定场景识别与小物体测试；可比较实际钥匙/钥匙扣微调与用户愿意使用的标记方案。标记代表配置绑定，不能表述成模型识别了钥匙身份；没有样本时不能完成钥匙验收。
- 桌面需定义区域；图像区域归属不能证明物品与桌面接触，也不能辨别是谁的钥匙。多个候选分别展示。
- 当前模型虽然保留laptop类别，生产适配仍只输出三种业务物品；laptop框本身没有开盖/合盖状态。既有development质检记录仅标记笔记本上下文，没有已核验的开/合盖状态数据集或钥匙标注；不能宣称旧素材已经覆盖。黑屏、笔记本漏检、手部遮挡、移出画面均不等于合盖。
- 现有通知在页面内。推理主机持续在线解决处理进程随合盖停止的问题，但提醒仍须出现在用户可见的主机页面；若希望手机等外部终端接收，需要另行确定接收端并接入，本轮不擅自发送。

## 实现划分

1. **规则与事实。** 建立受限的触发类型、时间范围、目标类别、区域和有效期；所有条件支持满足/不满足/未知，保留输入时间与来源。不提供任意Python、Shell或SQL执行。
2. **本地匹配。** 视觉更新与设备事件由本地程序判定；规则未命中时不调用模型。当前画面过期、断连、区域配置已变或只剩历史记录时，不能把“钥匙仍在”条件判真。
3. **Agent复核与通知。** 有效组合事件引用全部事实，Agent通过业务工具复核、生成消息并调用通知；保留事务去重与取消/额度检查。历史提醒必须明确“最后看到”，不能伪装当前确认。现有七工具的创建/查询/通知参数需要兼容扩展，不把系统事件硬塞进物品missing事件。
4. **合盖状态与接收端。** 为指定笔记本定义固定观察区域，优先验证局部开盖/合盖分类或几何方案，状态含打开、闭合、未知；只有连续有效证据确认打开→闭合才产生一次触发。持续闭合不重复提醒，重新确认打开才重置；启动时已合盖不伪造合盖动作。全图漏检后仍可复查固定区域，区域被遮挡/相机变位时保持未知。由常开主机负责处理，先复用页面提醒；系统睡眠/关机钩子不作为本次实现前提。
5. **验证。** 时间边界、不同事件顺序、重复触发、未识别钥匙/未配置区域、过期画面、取消/重启、提醒期间条件变化、关闭主机及通知不可见均需验证。模拟规则通过不等于钥匙实机或系统事件通过。

## 首个交付选择

先建立受限组合规则、持久化、去重与离线故障验证；视觉输入使用明确标记的受控事实仅验证逻辑，不计实机通过。随后核验固定机位的开盖、合盖、半合、黑屏仍开盖、遮挡/移出以及钥匙在场/不在场素材，冻结独立测试后实现本地视觉状态和钥匙适配。最后在常开主机上贯通真实视觉、Agent复核与提醒。该流程不以手机替代钥匙交付，也不要求训练云端对话模型。

## 资料依据

- [Home Assistant：触发、条件、动作](https://www.home-assistant.io/docs/automation/basics/)支持该规则组织方式；借鉴模式，不要求安装Home Assistant。
- [COCO类别](https://docs.ultralytics.com/datasets/detect/coco/)：现有预训练类别不包含钥匙。
- [Apple睡眠/唤醒通知](https://developer.apple.com/library/archive/qa/qa1340/_index.html)：可作为原生事件适配入口，但睡眠通知不是关机后运行保证。
- [Windows WM_QUERYENDSESSION](https://learn.microsoft.com/en-us/windows/win32/shutdown/wm-queryendsession)：应用应及时响应会话结束，不把阻挡关机作为提醒方案。
