# 本地识别改进分析

2026-09-07，Asia/Shanghai。基于 [九段视频评估](recognition-assessment-2026-09-07.md) 和本轮定向对照。以下是候选方案分析，没有修改生产模型、阈值、事件契约或首版范围。

## 先区分两个目标

检测层需要同时提高可见目标召回、降低错误分类；事件层需要减少“物品仍在却报持续未检测到”和错误出现。增加确认次数、延长等待或跟踪框不会自动提高单帧分类能力。最终仍需报告三类事件正确率、额外误报、延迟、CPU/RSS，不能只追求更多检测框。

现有证据包括：清晰完整杯子在官方PT和ONNX中得分均约0.01265，而大桶误作杯子的得分可到0.89。当前0.35阈值上下移动无法同时解决这两例；置信度也不是已经校准的正确概率。

## 本轮低成本方案对照

选取既有五个失败点：桌面手机15秒、工业手机11秒、马克杯20秒、厨房大桶37秒、夜间瓶子0秒。均从原视频顺序解码；这是刻意选出的失败样本，不能用于估算全局提升或替代保留验证集。

实际命令：

```sh
.venv/bin/python harness/artifacts/recognition-options/crop_probe.py
.export-venv/bin/python harness/artifacts/recognition-options/size_probe.py
```

两个诊断脚本和完整输出在忽略目录，脚本不读.env、不请求云端、不打开摄像头。裁剪使用生产ONNX、640、0.35，全图外增加四个宽高均为原图60%的固定角落窗口，保留20%原图宽高的相邻重叠；没有用人工目标框当自动ROI。尺寸对照使用已有官方YOLO26n PT、CPU、`rect=False, nms=False, conf=0.35`，分别640/960/1280；属于权重行为诊断，不是新ONNX导出或速度验收。共25次ONNX和15次PT推理，两条命令均退出0。

## 推荐次序

1. **先做模型能力对照。** YOLO26s、640、ONNX CPU是优先候选。官方同为端到端头的COCO mAP为n40.1、s47.8，官方CPU ONNX时间约38.9/87.2ms。前者不是本项目的准确率，后者不是本机延迟；只能作为值得评估的依据。先在相同素材和负样本上比较，确有收益后再修改当前锁定YOLO26n的架构与清单。保持无训练、无云端画面、相同类别和CPU路线。[官方型号数据](https://docs.ultralytics.com/models/yolo26)
2. **改善真实输入，按需评估ROI。** 当前CameraSource默认请求640×480。可评估更高采集分辨率、稳定对焦/曝光和桌面取景，记录设备实际返回值；高分辨率全图仍缩到640时，小目标并不会自动变大。ROI应从高分辨率原图裁剪、有边缘余量并保留全图通路，不能因目标离开裁剪区就声称离开摄像头。官方切片方法可以提高小目标的有效像素，但增加推理与合并开销，本轮固定裁剪未成功，故为有条件候选。[官方切片说明](https://docs.ultralytics.com/guides/sahi-tiled-inference)
3. **给未检测到事件增加局部复检。** 在现有三次出现/五秒有效未检测到契约内，临近确认时用新的有效画面对最后区域复检；严重模糊、曝光异常等应明确表达质量不足，不能推进有效缺失时间。弱候选可用于决定复检，但不能伪装成确认看见并刷新历史时间。预测跟踪框也不能替代真实检测。若需要改变采样档位、事件时限或领域状态，必须先记录设计变更，不能通过延长延迟让测试看起来通过。
4. **最后校准阈值与预算。** 在可靠的模型候选基础上，按类别验证阈值；新目标确认和已有目标附近复检可以采用不同证据要求，但不能无限用低分框维持“仍存在”。桶这类高分错误分类需进入负样本集。多路检测必须映射回原图并合并重复框，保留同类不同候选。额外推理优先放在待确认事件附近，避免常态四块加全图导致每轮5次推理。

较高输入尺寸需要重新导出当前固定形状ONNX、生成独立manifest并核对PT输出，不能仅改一个配置值。YOLO26另有传统检测头可作为后续对照，但本项目当前适配器只接受端到端`[1,300,6]`输出，切换检测头需要同时验证导出语义、输出解析和NMS，不能随意切换参数后仍沿用现有适配器。[官方双检测头说明](https://docs.ultralytics.com/guides/end2end-detection)

## 如何决定是否采用

当前九段素材已经用于发现问题，视作开发诊断集；另取固定桌面、真实类别进出与无目标干扰视频作保留验证，按视频而不是相邻帧划分，避免同一个物体/镜头泄漏到两边。53个复核帧不足以稳定校准阈值，也不是独立用户标注。

先比较n640与s640的逐帧正确框、漏检和误报，再比较事件结果；要求清晰可见手机不再因同一类漏检形成错误事件，同时不能用更多桶/锅误报换取杯子召回。对候选方案记录三类事件目标、负样本每小时误报、首次确认与通知延迟、稳态CPU/RSS、p95推理和失败恢复。Mac/Windows实机与90%原验收标准保留。

如果坚持YOLO26n权重完全不变，可做采集、ROI和事件复检，但根据本轮失败点，不能保证它们能补足模型分类能力。模型候选对照优先级因此高于全局降阈值、无差别放大或增加连续确认次数。
