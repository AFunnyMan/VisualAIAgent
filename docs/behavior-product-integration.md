# 行为、统计与基础情境规则

本轮采用当前固定机位的实验模型，接入正式Streamlit页面。物品模型、行为阈值和原有250ms行为新鲜度保护保持；接入产品不代表动作识别质量、长期稳定性或Windows实机验收已经通过。

## 使用

1. 正式入口仍为 `uv run streamlit run app.py`。在侧栏展开“实验行为识别”，选择启用、确认本地姿态/饮水模型清单，再点击开始观察。
2. 当前机器已有实验清单时页面会预填 `harness/artifacts/behavior-20260910-r02/{posture,drinking}-run/training-manifest.json`。不会自动启用、下载或训练；其他机器需先准备合法清单及对应权重。
3. 当前固定机位建议保持完整16:9画面。页面中的原“观察范围”是已有采集裁剪，不是自定义语义区域；本轮没有新增区域标注能力。
4. “行为与统计”显示当前姿态、疑似饮水、每日有效在座/空座/站立时长、离座和疑似饮水次数、未知时长及最近事件证据。
5. “情境规则”可创建、编辑、启停和取消长期规则。休息提醒默认不存在；选择“连续有效在座达到时长”，设置分钟数和提醒内容即可启用，初始建议45分钟。
6. 基础情境示例：触发为离座，时间填18:00，物品选手机，区域选右侧，提醒内容填“离开前检查手机”。规则仅在触发时核验，不会因稍后超过18点而补发。

自然语言示例：

- “今天确认在座多久？未知时间不要算进去。”
- “我最近有哪些离座记录？”
- “连续有效在座45分钟提醒我休息。”
- “离座时如果手机仍在右侧，提醒我检查手机。”
- “把这条规则改为19点后触发。”

提醒仅在页面内展示。钥匙、笔记本合盖、手机使用、专注推断、自定义命名区域和外部推送尚未支持，不用现有物品冒充这些能力。

## 运行与数据接口

单个物理摄像头经共享最新帧服务向两个独立消费者提供带原始采集时间的画面：物品保持1/2秒采样，行为目标10fps。慢消费者跳过旧帧，不排队补处理。正式与旧实验入口复用相同推理、预处理、人体关联和状态机代码。

行为启动或模型配置失败单独显示，物品可继续工作。每次启动生成新的场景会话ID，物品与行为共用，避免跨视角/会话拼接条件。行为事实记录实际模型SHA前缀；实验分类模型清单验证完整预处理契约、类别及ONNX SHA。人体辅助沿用已校验的正式物品模型。

`BehaviorObservation`独立携带姿态、饮水、时间、有效性、模型、场景、来源和已确认事件；`BehaviorEvent`包含起身、坐下、离座、返回在座、疑似饮水。SQLite升级至v3，迁移前备份；旧物品、任务、通知及调用记录保留。

行为仅保留最新观察、合并的状态区间和事件，不永久保存每帧分类历史。事件截图保存在本机；规则保存触发时的配置版本、行为事实、物品候选、时间及证据关联。

七工具数量不变，兼容旧物品调用：

| 工具 | 本轮扩展 |
|---|---|
| get_current_scene | scope=scene/behavior/statistics；统计可传YYYY-MM-DD日期 |
| find_object | 原物品最后观察查询保持 |
| search_events | scope=objects/behavior/rule；规则复查限定rule_id/event_id |
| create_watch | target=watch/rule；规则action=create/update/enable/disable；局部更新仅改提供字段 |
| list_watches | 一并返回物品关注与结构化规则 |
| cancel_watch | target=rule时watch_id参数填写rule_id |
| notify_user | 自动规则执行中限定该规则和事件，须先场景查询再触发证据复查 |

规则局部更新默认保留未提供字段；移除时间条件使用clear_after_time，移除物品及区域条件使用clear_object_condition。UI编辑表单展示完整规则。

## 计时与触发语义

- 姿态与疑似饮水分别表达，可以同时成立。在座不代表学习或专注，疑似饮水不证明吞咽或水量。
- 相邻有效样本间隔最多250ms；未知、故障、回拨或场景变更不延续有效在座计时。首次启动不伪造动作。
- 同一进程观察会话内、采集单调时钟与墙钟一致的长断档记为未知，不记为在座/离座；停止、暂停、进程停机或时钟跳变不补算监测时长。
- 按Asia/Shanghai日界线裁切统计，跨午夜正确拆分。连续在座不因午夜重新开始。
- 疑似饮水按动作事件计次；空座时长包括启动时已经空座的有效区间，离座次数只计确认事件。
- 休息阈值仅在跨越时检查其他条件，一段在座不反复触发；未知不恢复已消耗的提醒资格，确认空座后才重置。
- 物品条件要求触发前最近三条完整物品观察连续有效且符合类别/区域；故障、场景不同、旧画面与缺失物品不会满足。物品使用其原1/2秒采样容差，不套用行为250ms间隔。
- 条件只读取触发处理入口前已提交、且采集时间不晚于触发的事实。通知描述触发时观察，不把快照说成现在。
- 规则持久化、版本化、原子领取；重复投递不能重复领取。修改/停用/取消使排队旧任务失效；通知按规则版本/事件去重。
- 本地观察、计时、等待不调用云模型。只有相关触发进入现有串行Agent队列，并共用自动日额度；未连接、额度不足或失败走标记明确的本地降级通知。

## 验证入口与待实测

```sh
uv run pytest -q
VAA_RUN_LIVE_API=1 uv run pytest tests/agent/test_behavior_live.py -m live_api -q
uv run python -m scripts.check_behavior_integration \
  --posture-manifest harness/artifacts/behavior-20260910-r02/posture-run/training-manifest.json \
  --drinking-manifest harness/artifacts/behavior-20260910-r02/drinking-run/training-manifest.json \
  --output data/acceptance/new-unique-integration-run --seconds 30
```

第二条会产生真实模型调用，使用隔离测试事实；第三条访问真实摄像头与真实本地模型，独立数据目录且不调用云模型，不要求用户动作。输出目录必须不存在。

开发视频一致性、受控事实规则测试、组合负载均不替代独立动作质量验收。最后仍需用户演示坐站/离座/返回、杯口到嘴与靠脸负例，核对实际统计及一条真实离座＋物品区域提醒。性能专项、物品质量改进与训练、钥匙/合盖训练按用户要求暂缓；Windows实机仍依赖对应测试设备。
