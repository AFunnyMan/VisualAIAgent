# 2026-09-08 OBSBOT 实机验证

本轮由用户明确授权打开已接入的实体摄像头。测试设备为当前 Apple M2 Pro Mac、OBSBOT Meet StreamCamera、AVFoundation index 0，实际输入 640×480。正式配置保持 YOLO26n ONNX、0.35 阈值和一秒采样；没有更换生产模型。相机原图、事件截图、数据库及完整运行结果仅保存在被忽略的本机目录。

## 已观察结果

首次单线程采集 3.029 秒得到 93 帧，退出正常。首次通过正式双线程工作器运行 60 秒，采集中有 57 条有效观察，但停止时进程退出 139，原生崩溃栈位于 AVFoundation 的读帧调用，不能算验收通过。

修复将摄像头释放移到拥有读帧操作的采集线程；停止方只发送退出信号并等待，超时则保留工作线程和错误状态，防止并发重开。真实复验同一条 60 秒命令退出 0，56 条有效观察，4 条启动前 stopped 状态，没有运行期断连/过期状态。该次推理 p50/p95 为 74.54/77.36 ms，峰值进程 RSS 401.72 MiB；短时数据不替代三十分钟测试。

随后同一 VisionWorker/CameraSource 连续三次启动、取得新画面、停止全部通过，各轮取得 3 次有效观察；停止耗时分别 67.90、58.40、66.47 ms，最终均 stopped、无存活工作线程、无回调错误。此项验证底层真实设备生命周期，不能代替完整应用界面验收。

初始桌面画面的 n 模型框落在饮料罐上，旁边塑料瓶没有被框出，提示类别误识别与漏检仍存在；初检时尚无用户提供的场景操作标签，不能据此计算误报率或三类事件准确率。后续首轮操作核对见下文。

## 用户操作与计分

可使用新增的本地辅助台，在真实操作后点击对应标记。标记是人工操作记录，不是识别成功证明。辅助台只记录本地视觉、事件及性能，不调用 Agent 或云端，不录完整视频。

```sh
uv run --locked python scripts/camera_acceptance.py \
  --camera 0 --duration 1800 \
  --output data/acceptance/obsbot-new-session --port 8765
```

输出目录必须尚不存在；启动前关闭其他使用同一摄像头的测试或应用。页面位于 `http://127.0.0.1:8765`。默认从首个有效新画面开始计时三十分钟，提前停止不算完成；推理/采样故障和停止失败必须单独报告。

1. 将手机、杯子、瓶子移出视野，完成布置后点“空桌面已就绪”，保留一分钟检查背景误报。
2. 一次只测试一个类别。真实放入后立即点该类“已放入”，保持至少十秒；真实移出后立即点“已移出”，保持至少十秒。
3. 每类重复十轮，共六十个预期事件。把物品完整放入视野，维持固定光照；漏检也按原计划记录，不仅保存成功轮次。
4. 按人工操作时间匹配实际事件，核对类别、区域、证据及时间；没有匹配的预期事件为漏报，额外事件单列为误报。同一类别多个物品需另测候选，不能用类别出现事件代替个体计数。

总体及每类至少 90% 的原始验收条件保持不变。遮挡、物理断连、完整应用内真实 Agent 提醒和 Windows 11 实机仍按 [用户辅助验收](user-acceptance.md) 分别执行。稳定性通过不能关闭这些验收项。

完整执行进度与后续结果以 [build-log](../harness/build-log.md) 为准。
