# 固定场景物品 R03 问题与修复

2026-09-17，Asia/Shanghai。本轮针对杯子/手机/瓶子物品检测的 R03，不是饮水模型 R03。用户新增的 development_pic 共51张，均1920×1080。私人图片留本机，正式权重未替换。**用户确认后已完成R04/R05训练，最新结果见[两轮训练结果](scene-r04-r05-results-20260917.md)。下方“未训练/待确认”为此前标注复核里程碑的历史记录。**

## 已确认的问题

1. **同一物体重复出框。** 旧实机180次有效采样中，13次同一杯子输出两框，IoU约0.987。端到端输出仍可能重复，而原解码仅做置信度过滤，没有近重复抑制。杯缩放复查在主分支已有杯时不会执行，不能将这一缺陷归因于复查。重复框虽未产生重复类别事件，会夸大查询/UI候选数。
2. **训练覆盖不足。** 旧现场数据仅54张（36训练/18开发验证），大量画面来自同一视频相邻姿态。新图包含闭合笔记本背景、手机背面/亮屏/截断、杯位变化及手遮挡，与旧R03训练画面构图存在差异。新图已复现边缘杯、手机漏检及手机旁额外错误框；具体计数在标注冻结后报告。不能只凭固定场景就假定所有日常状态已覆盖。
3. **旧高分不能作为验收。** 18图参与epoch选优，三段61采样回放也与开发数据有关。此前实机仅一次会话、每类一次移出返回，未满足每类十次与90%事件目标。公共误报增加是诊断信息，不单独否决固定场景；真实固定场景的额外误报仍须验证。

## 程序修复

正式和实验解码共用同类近重复抑制：按置信度稳定排序，仅在IoU≥0.97时保留较高分框；不同类别和普通重叠/相邻物品均保留。不改变置信度0.35、匹配IoU0.5或事件三次/五秒规则。该几何规则不能证明两个框一定是同一身份；几乎完全重合的真实同类物品仍是能力边界。

导出检查同时比较去重前与部署后结果，防止去重掩盖PT/ONNX差异。二者任一失败，评估命令均失败。训练、评估与部署的默认后处理一致。

## 新数据质量与隔离

全部51张来自约四分钟连续采集，整组作为development训练，不随机逐图拆出“独立测试”。沿用旧数据的整视频train/val/test分组和原四组部署选优指标；final-test不读取。

首批人工坐标标注在root渲染复核中发现偏移，被拒绝，保留本机rejected版本；必须逐张重做、渲染和复核后才能训练。不能以JSON可解析或坐标未越界代替图像质量检查。

本轮验证仍属开发/历史回归；51图加入训练后的检出率只能称训练样本回归，不能称独立准确率或真实事件通过。新连续视频/实机独立事件与长时空场、Windows验收仍须后续完成。
