# 行为识别实时性能优化（2026-09-20）

## 原因与约束

现场入座时，原始姿态模型持续输出 seated，但推理与同步保存长尾导致结果超过250ms时效，时间线也因相邻采样间隔超过250ms而重新确认。旧诊断采用异步读取最近耗时，仅用于定位，不能与本轮同帧分位数作为严格受控A/B。详情见 [进度](../harness/build-log.md)。

本轮不改模型权重、分类置信阈值、250ms时效/连续性限制或动作定义。保留暂停、断连、过期、不足采样为未知的保护。

## 实施

- SQLite启用WAL，所有连接显式FULL同步。既有数据库切换前使用SQLite Backup API一致备份；已有schema迁移备份可复用，已为WAL不重复备份。失败明确报错，不静默继续。
- 一个轻量连接在应用存活期间保持打开，避免每次操作后关闭最后连接而反复checkpoint。后台线程确认结束后关闭该连接；对象回收有兜底。临时库1000次FULL写入有限对照约0.807秒→0.182秒，仅为数据库微基准。
- 姿态与饮水只有在尺寸、ROI、期望源尺寸完全一致时共享同帧预处理张量；不一致仍独立。真实权重单张现场图的新旧路径概率逐项相同；单槽辅助任务仍绑定输入，不能拿上一帧结果冒充本帧。
- 同帧诊断记录推理、回调、发布前/保存后帧龄、采样间隔、原始分类和最终状态。内存最多1200条，不保存图像；仅测试脚本显式导出本地日志。辅助任务并行，阶段耗时不能简单相加；共享预处理只在姿态阶段计一次，以同帧发布/保存年龄评估端到端延迟。
- 保留此前空规则只读快速路径与5秒统计刷新。有限静态线程对比支持保留现有姿态/饮水各2线程、人体4线程，不为参数变化而变化。

## 复测方法

先停止网页观察服务释放摄像头，再在项目根目录运行：

```sh
.venv/bin/python scripts/behavior_runtime_soak.py \
  --output data/behavior-perf-unique-run \
  --history data/memory.sqlite3 --duration 600 --model r05
```

输出目录必须不存在。脚本从历史库一致备份到隔离目录，运行真实USB和正式Runtime、R05、杯复查、姿态/饮水，以及定时页面读取负载（轻读0.5秒、统计5秒，轻读略高于真实行为页的1秒频率）；禁止API调用，不录完整视频。该脚本不包含浏览器渲染，也不提供人工动作真值，不能用稳定输出推断识别准确率。前10秒启动期与稳定期分开统计。完成后正常停止并关闭数据库连接。

## 页面负载诊断

独立Runtime长测不包括Streamlit渲染。恢复真实页面后仍大量超时，未据独立长测宣布修复。Python线程采样实际命中Streamlit每次片段刷新后的`gc.collect(2)`，以及本日约1.58万区间的历史统计解析。使用已安装框架支持的`runner.postScriptGC=false`停止每次刷新强制全量回收，保留Python自动GC。仅此修正的600秒网页抽样仍有123/4937条stale，未通过；RSS在该窗口波动，不能据此推断长期内存无增长。

进一步将预览/对话调整为每秒刷新、笔记本历史5秒刷新；历史证据须明确勾选才读取图片。标签页仅执行当前选中页，后台识别和任务仍由独立Runtime管理；切换标签不停止观察。

## 数据库恢复

如需回退：完全停止应用及所有数据库写入；保留当前库作为原件；从选定的 `data/backups/*.sqlite3` 用SQLite Backup API恢复到临时库，执行 `PRAGMA integrity_check` 并核对版本和记录，验证后替换。不要单独复制活跃的数据库主文件而遗漏WAL。恢复旧schema备份后仍按原迁移流程升级。本轮不改变备份保存范围或删除历史数据。

## 实测结果

Mac M2 Pro、Python 3.11、锁定的Streamlit 1.63.0、ONNX Runtime CPU。物品R05＋杯复查、姿态R04＋饮水R03，分类阈值和250ms保护未变。汇总见[机器可读记录](../harness/evaluations/behavior-performance-20260920.json)。

- 独立Runtime 600秒：5986次结果，启动10秒后5889次，fresh占99.949%，4次采样间隔超过250ms；保存后帧龄P95 86.790ms。该项先通过，但旧网页复验失败，保留失败结果，不混为最终网页表现。
- 最终真实网页720p：23:11:52—23:20:28，约516秒；启动10秒后5059次全部running，保存后帧龄P95 66.361ms、最大189.630ms，采样间隔无超过250ms。
- 最终真实网页1080p：23:20:29起固定300秒；启动10秒后2899次全部running，保存后帧龄P95 71.332ms、最大244.772ms，采样间隔无超过250ms。包含空座997、站立87、在座1806、状态确认期间未知9次；未知未伪改为在座。实际截图确认人在画面中，页面连续有效在座累计至3分钟。
- 两个自动化行为页面在1080p阶段同时打开约85秒，之后一个结束；没有把整个5分钟称为双页面压测。720p变化来自摄像头重启后接受请求，另显式1080p验证以排除此混杂；不是严格单变量A/B。
- 两段启动期分别有27、13次stale，保留启动保护。480秒只读轮询跨越一次主动切分辨率，4776条去重中含一次stopped和13次启动stale；轮询可能漏中间结果，端到端分位数采用同帧完整日志。
- 同窗口RSS约293—538MiB，起点463、终点478MiB，存在回落，不呈持续单调增长；不代表多日无内存泄漏。无浏览器pageerror。正式数据库integrity_check为ok、journal_mode为wal。
- 最终`.venv/bin/pytest -q`：443 passed、1 skipped、5 deselected / 17.70秒；Ruff、格式和差异检查通过。覆盖WAL备份/并发读取、同帧与契约不匹配、过期拒绝、初始化失败清理、标签切换后任务保留和图片按需加载。

私人线程栈、同帧记录、数据库副本与截图保留在本机`data/behavior-perf-20260920-soak/`，不提交。真实网页通过Playwright/Chrome访问同一本地Streamlit服务，独立脚本长测方法见上。测试期间环境覆盖API Key为空，不修改.env；结束后恢复普通启动服务和原配置。

本轮证明性能路径与现场连续在座恢复，不等于独立饮水、离座、手机/杯事件质量全部验收。Windows实机和真实API本轮未测试；下一步由用户按正常坐姿、饮水、离开及返回复核动作。
