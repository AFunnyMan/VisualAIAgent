# r02之后的行为识别改进分析

2026-09-10，Asia/Shanghai。本文为分析与诊断，未修改正式或实验运行时代码、未重新训练。基线结果见[独立测试报告](behavior-training-r02-20260910.md)。

## 优先级与依据

1. **姿态事件状态管理**：把当前可确认状态、上次稳定状态上下文、候选动作和采集健康分开。低分类置信可暂留约0.5—1秒历史上下文，但当前输出仍unknown，不能将该时段计入确定在座/离座时长。恢复后须重新连续确认；起身还须有可见连续过渡证据。断流、陈旧帧、逆序时间、长时间不确定、无法排除遮挡时切断事件链。fresh只代表新鲜，不证明没遮挡，不能仅凭fresh安全桥接所有unknown。
2. **饮水采样与确认单独设置**：先对照5fps与10fps，10fps下0.25秒通常有2—3个采样点；试验短窗口连续2—3个高置信样本，实际按时间戳和最大帧间隔约束，事件结束确认与重复抑制单独设置。候选参数未校准；缩短确认会增加拿杯靠脸误报，必须同时计分。姿态保留较慢确认，不能全局一律改短。先验证固定10fps，再考虑按需加速；仅靠2fps低频检测触发加速可能先漏掉整个短动作。CPU每模型约9—10ms只说明有实验空间，不是全应用10fps验收。
3. **饮水局部输入**：目前1920×1080等比缩放到320×180，再填充到320方形；嘴和杯口细节可能过小，这是待实验证明的解释。固定机位先选覆盖自然头部、手和杯子运动范围的宽松ROI；保留完整姿态分支，饮水分支用ROI的320/384输入。训练、验证和ONNX推理严格同裁剪/缩放，机位变化必须使ROI校准失效。ROI从开发素材设定，不围着测试漏帧量身定制。
4. **训练样本分配**：饮水55正例/453负例，且仅约6次独立训练饮水。按动作片段控制抽样、适度增加正类损失权重，保留拿杯不喝/摸脸/擦嘴等困难负例。重复相邻帧不等于增加独立动作。现有全画幅等比填充已处理默认随机裁剪风险，不应误写成尚未修复的bug。
5. **升级条件**：局部分类仍分不清杯口与嘴部关系时，才对照杯框、头肩/手腕关键点与轻量短序列模型。默认YOLO Pose的17个关键点没有精细嘴唇与杯口，当前视角又可能遮住下肢，因此不能把Pose或3D视频模型当作必然更准的替代品。

## 本次实际诊断

仅读取r02既有video-predictions.jsonl，不再执行模型：试验短暂unknown期间保留旧姿态上下文、仍按原.5秒重新确认。此前漏掉的起身和坐下被补回，姿态事件从6/8变为8/8，额外姿态事件0；饮水保持1/3。产物在本机harness/artifacts/behavior-20260910-r02/unknown-context-diagnostic.json。

这是事后反事实诊断，说明前态清除确实造成了两次漏报；不是经过遮挡/故障验收的可部署实现，也不是新的独立准确率。旧最终测试现已用于改进分析；后续按其结果设计的新候选必须在新素材上作最终验收，不复用旧成绩证明泛化。

## 下一轮实验顺序

固定当前权重先对照状态管理与独立采样/确认参数，明确事件收益及新增误报；随后固定时序，比较原全图饮水与ROI饮水，最后单独对照类别权重。避免把采样、输入、数据、模型大小和轮数一次全改后无法判断收益来源。指标按各类动作召回、额外事件/小时、延迟、未知占比和长时故障恢复统计；短饮水单独分组。

现有视频足以开始以上开发实验，无需先要求用户继续补拍。确定候选后，再需要独立短饮水/普通饮水、拿杯不喝/摸脸等反例和较长自然在座录像作最终验收。无需跨房间、换人或强制换衣服。先用当前YOLO26n-cls，不增加云端调用。

## 资料与推断边界

- [Ultralytics分类](https://docs.ultralytics.com/tasks/classify/)说明分类输出是整图类别，并支持自定义变换及训练/验证一致性；ROI优先是结合本项目分辨率与失败记录的工程假设，尚未证明优于全图。
- [Ultralytics Pose](https://docs.ultralytics.com/tasks/pose/)列出默认17个人体关键点；关键点可作动作辅助，不直接提供饮水语义。
- [PyTorch CrossEntropyLoss](https://docs.pytorch.org/docs/stable/generated/torch.nn.CrossEntropyLoss.html)支持类别权重以应对不平衡；权重大小及误报代价需开发集验证。
