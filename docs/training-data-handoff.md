# 下一轮训练：数据提供清单

日期：2026-09-09。用户负责真实物品和场景布置，提供原始图片或短片及简单说明；助手负责抽帧、去重、逐图核对标注、数据划分、训练和回归。无法从画面确认的物品再单独询问，不把模型预测直接当真值。本次只是交接说明，没有采集或启动新训练。

## 先交一小批，不必一次拍满

先提供20—30张有差异的原始图片，或5—8段约20—40秒的原始摄像头短片。覆盖当前杯子、瓶子、手机、易混物和空场景即可。数量与时长是本项目方便操作的首批建议，不是训练成功门槛；我会先检查尺寸、遮挡、重复程度与标注可行性，再明确还缺什么。

第一批通过后，逐批补充，目标是累计约300—500张有差异的现场样本，再按完整会话分配训练/验证/测试；不是300—500张全部用于训练，也不是保证达标的数量。大量相邻静止帧不能算多样性。公共数据与已有资料由助手整理，用户优先提供网上找不到的实际机位素材。

## 拍什么

| 内容 | 具体布置 | 建议覆盖 |
|---|---|---|
| 当前透明杯，最高优先 | 平常位置及容易漏检的位置；左/中/右、近/远、靠边；转动杯柄或改变朝向；正常使用时可能存在的水位 | 清晰无遮挡、部分遮挡、画面边缘截断都保留，并注明 |
| 其他杯子 | 手边不同形状/透明度/材质的杯子 | 有条件可提供3—5个杯实例，其中至少1个完全留给最终测试；不要求专门购买 |
| 瓶子 | 水瓶、饮料瓶等实际常见瓶；杯与瓶同框 | 防止提高杯召回时把瓶子都改判为杯 |
| 手机 | 正反面、横竖放、不同距离、靠边；与杯/瓶同框 | 当前现场手机数据不足，不能全部只拍杯子 |
| 易混物 | 实际环境会出现的碗、桶、盆、花盆等 | 没有杯/瓶/手机时拍一组，再与真目标同框拍一组 |
| 无目标场景 | 移出杯/瓶/手机，保留真实桌面、正常杂物；人或手可正常经过 | 用于检查无目标时误报，不把布置成纯色空背景当唯一负例 |

无需穷举所有组合。优先保持后续真正使用的摄像头机位，改变物品摆法和实际光照。分几次采集，比如白天、晚上、另一日；每次独立保存一个会话。能看清物品特征的常见状态和真实困难状态都要有，不能只挑当前模型成功检出的画面，也不能全部都是极端困难画面。

若目前只有一个杯子也可以开始，说明“只有cup01”；另一天同杯测试可以检验该杯新会话表现，但不能声称对新杯也可靠。完全遮挡/完全画外素材可保留作“不确定/未看见”的事件测试，不强行给不可见物体画检测框。

## 怎样拍

- 优先使用当前USB摄像头的原始画面，保持实际使用的分辨率；已有1280×720即可起步，不必为了训练强制改成4K。手机拍桌面的照片可作补充，不能替代主摄像头机位数据。
- 图片接受JPG/PNG；短片优先MP4（H.264），已有MOV也可以先提供再检查解码。保留原文件和时间顺序，不自行缩成640、裁出单个杯子或反复压缩。
- 不用带浏览器界面、检测框、置信度文字的识别页面截图。画面本身的真实物品文字可以保留。
- 拍短片时，每次摆好后让手离开目标前方，静止约3—5秒，再换位置/朝向；需要遮挡样本时另外明确做一次部分遮挡。正常使用会有的轻微模糊可保留，不刻意制造整段无法辨认的画面。
- 仅收集有明确用途的短片或图片，不需要全天录像。私人素材留在本机目录，不上传公共仓库或云端标注平台。

## 单独准备最终验收素材

留出较晚日期的完整会话；有其他杯子时再留出至少一个从未进入开发数据的杯实例。把这些原始素材直接放到`final-test`目录，并注明“最终测试”。该目录只做文件完整性与清单检查，待数据、参数和候选模型固定后才解封标注/评价，不用于训练、选epoch或调阈值。

同一片段抽出的所有图片必须属于同一部分，不把一段视频随机分给训练和测试。分组隔离的依据是会话及物体实例，不只是文件名或图片哈希。[分组验证说明](https://scikit-learn.org/stable/modules/generated/sklearn.model_selection.GroupKFold.html)。

为了验收出现/消失流程，可另外提供一段约60—90秒的连续短片，保持机位不动：

1. 目标不在画面，约10秒。
2. 放入目标，手离开后保持约15秒。
3. 部分遮挡约5秒，恢复可见后保持约10秒。
4. 完全移出画面约10秒。
5. 放回并保持约15秒。

操作时间不必精确，片段可略长；记录大致动作时刻即可。杯/瓶/手机后续分别验证，单次片段仅作流程初筛，不替代每类十轮验收。另有目标始终在场/始终不在场的持续观察，仍需后续实测，不能从短片外推长期误报率。完全遮挡应注明，不能把它与真正移出混为一个动作。

## 放在哪里、附什么说明

本机接收目录已建立：`data/training-inbox/`。`data/`已被Git忽略，素材不会随正常项目提交进入仓库。目录内的`README.txt`是填写模板。建议结构如下，文件和会话名均为示例：

```text
data/training-inbox/
  development/
    20260910-day-01/
      clip01.mp4
      notes.txt
    20260910-night-01/
      image001.jpg
      image002.jpg
      notes.txt
  final-test/
    20260911-newcup-01/
      clip01.mp4
      notes.txt
```

每个会话只需一个简单`notes.txt`，例如：

```text
日期/时段：2026-09-10 白天
摄像头/机位：当前USB摄像头，机位未改变
物品：cup01=原来的透明杯；bottle01=矿泉水瓶；phone01=常用手机
clip01.mp4：只有cup01；杯柄转到背面、右侧靠边；末段有手部分遮挡
image001.jpg：杯瓶手机均不在画面，只有桌面和碗
用途：开发素材；同一个cup01在其他文件里仍叫cup01
其他：有/无完全遮挡；是否改变分辨率或摄像头设置
```

无需写JSON、量坐标或安装标注软件。我会保留原件，核对场景说明，按冻结规则组装数据。若沿用80类头，标注会覆盖画面中实际存在的相应类别；只要求你说明难以从外观分辨的物品。已标注资料也可提供，但要带上类别名称表，避免三类编号0/1/2与COCO编号39/41/67混用。[官方标注与质量建议](https://docs.ultralytics.com/guides/data-collection-and-annotation)。

放好后回复“数据已放入data/training-inbox”，或直接给出已有本机文件夹的绝对路径；无需逐个上传聊天。收到文件后先做质量检查并报告覆盖缺口，再进入数据冻结和下一轮训练。训练参数及实际结果继续写入根目录[训练日志](../训练日志.md)。
