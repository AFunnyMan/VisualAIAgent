# 需要用户辅助的最终验收

真实千问 API 已配置并通过独立用例，公开视频也已验证出现/未检测到提醒、断流和重启。2026-09-08 当前 Mac 已接入 OBSBOT，并完成短时采集及停止崩溃修复后的启停复验；实际范围见 [摄像头验证记录](camera-validation-2026-09-08.md)。下列 USB 设备及现场场景仍需用户操作，Windows 11 x64 尚需实机条件。已完成的自动验证及复现命令见 [千问说明](qwen.md)，不能据此省略硬件验收。每次用独立 `VAA_DATA_DIR`，不清理已有私人数据。测试失败保留事实和样本，不修改通过标准。

## 1. 环境与设备

在 Mac 和 Windows 分别保存 `uv run --locked python scripts/doctor.py` 输出，补充 CPU、内存、摄像头型号、连接方式、实际画面分辨率和采样档位。Windows 需要原生 Windows 11 x64；GitHub 托管 Windows runner 的结果另列。

准备手机、杯子、瓶子，固定光照与摄像头位置。在应用点击开始，确认画面和检测框；点击停止再开始，检查设备被释放且不重复启动。切换标准/省电档要先停止再开始。

## 2. 事件与证据（两平台分别执行）

每类物品十次放入、十次移出，共 60 个预期事件。每次放入至少保留三次有效采样，移出至少保留五秒有效未检测到（省电档可能在下一采样确认）。每条记录：类别、操作时间、预期事件、实际事件 ID/确认时间、区域、证据 ID、漏报、额外误报。

事件正确率 = 正确匹配的预期事件数 / 预期事件总数。总体及每类目标均至少 90%；额外误报单独计数。不能以只挑成功截图替代评分。

另测试：两秒遮挡不能提前缺失；两个同类物品显示多个候选；未知类别/无历史明确未知；断开摄像头五秒、停止、遮住导致输入故障和重启空白期间不能推测物品消失。重启后历史时间与证据仍可打开，当前状态在新画面前必须未知。

## 3. 真实模型

本开发机 `.env` 已配置；更换机器、Key 或模型时，在本地填写完整配置后执行显式付费验收开关（切勿将 Key 写入命令历史）：

Mac：

```sh
VAA_RUN_LIVE_API=1 uv run --locked pytest tests/agent -m live_api -v
```

Windows PowerShell：

```powershell
$env:VAA_RUN_LIVE_API = '1'
uv run --locked pytest tests/agent -m live_api -v
Remove-Item Env:VAA_RUN_LIVE_API
```

这组测试使用临时数据库和明确测试事实，调用真实 API；它验证真实工具选择和持久化，不能替代摄像头质量。缺少显式开关或配置会跳过，跳过不代表通过。

随后在应用依次自然语言查询最后位置、创建关注、取消关注、重新创建并布置相关物品事件。检查工具执行摘要和真实任务/通知，提醒 source 必须为 Agent；fallback 只算降级成功。确认取消/到期后迟到提醒被拒绝，重复事件不增加有效通知。

记录实际提供商/模型、模式、请求尝试次数、工具名称与是否成功、Token 用量及是否完整；不要分享 Key、原始私人聊天或摄像头图片。模型不得声称知道谁拿走或物品具体身份。

## 4. 持续运行与成本

为独立本地视觉性能记录及人工操作标记，先停止 UI 摄像头，在两个平台分别运行（输出目录必须尚不存在）：

```sh
uv run --locked python scripts/camera_acceptance.py --camera 0 --duration 1800 --output data/acceptance/new-camera-session --port 8765
```

脚本会真正打开摄像头，在 `http://127.0.0.1:8765` 展示最新画面和真实操作标记按钮，输出目录包含进度、完整采样与汇总、操作时间及独立视觉记忆。记录 CPU（单核 100%，多核可超过 100%）、RSS、推理 p50/p95、有效/故障采样和最大采样间隔；脚本不调用任何云模型。首个有效新画面后才计三十分钟，断连、采样间隔超限、停止失败或提前中断均不能通过。页面人工标记不自动证明90%识别质量。旧 benchmark.py 仍可作短时性能采样，正式持续验收使用辅助台的完整判定。

另外在完整 UI 中保持十分钟无相关事件，确认视觉正常且模型请求数不增加；触发一次相关事件，记录事件确认到通知的延迟、是否仅一次提醒。记录 API 失败/断网及自动额度耗尽时本地视觉是否继续、降级来源是否明确。
