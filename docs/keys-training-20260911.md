# 固定场景钥匙检测试验（2026-09-11）

> 2026-09-12 用户暂时取消钥匙功能。本报告为保留的历史实验记录；以下优化建议和验收步骤均暂停执行。

状态：r04隔离数据、三轮有效试训、ONNX导出和development评估已完成；最新候选固定0.35阈值的整片分组开发val召回仍为0，**试验失败，不得接入正式程序或进入holdout验收**。r01标注与其中断训练已废弃。该模型为独立单类 `key` 检测器，不修改正式三类物品模型。

## 数据隔离与标注

本数据准备、训练和development评估流程只使用来源登记表中七段 `development` 视频，并在抽帧前调用 `verify_development_sources` 核对内容 SHA-256；该流程没有读取、抽帧、训练、调参或预测登记为 `holdout` 的 `验收2026-09-11 23-08-00.mkv`。数据和模型位于被 Git 忽略的 `harness/artifacts/keys-20260911-r01/`，私人画面不提交、不上传。

整段视频固定分组：`23-01-33` 和 `23-02-14` 仅在 train，`23-05-02` 仅在 val；另四段无可见钥匙的视频提供负例并按整片进入 train 或 val。r02冻结数据共30帧：train 14、val 16；11个钥匙框、19个无可见钥匙帧。`23-02-14` 的4秒画面包含桌面钥匙并已标注，20秒与36秒被笔记本完全遮挡，只作为“当前帧无可见钥匙”样本，不代表物品离场。原图1920×1080。train框宽70—190像素、高54—171像素；val中的5个钥匙帧均来自同一视频中手机右侧的相近摆放，只能看到画面下缘截断部分，框宽85像素、高143像素并触边，不能称为五个独立场景。

r01曾把空白桌面标成钥匙，并在部分训练框中包含过多桌面/手部；复核中还排除了画面边缘的杯沿碎片。CPU探针和最终训练都使用了这版错误数据；最终训练在第3轮中途人工停止，没有导出，其权重和指标全部作废。r02由逐张1920×1080原图复核后的tight boxes重新生成，输出目录与r01分开。

人工逐帧目检将钥匙、钥匙扣和金属钥匙作为一个目标。手部使目标身份或边界不清的帧不抽取；出框样本只框可见部分并记录 `truncated=true`，不臆造画面外边界。生成入口为 `scripts/prepare_keys_data.py`；manifest保存源视频SHA、帧号、时间、图片SHA、尺寸、框和整片分组。

## 训练与开发对照

训练入口 `scripts/train_scene_model.py` 新增可重复的 `--class-name key` 单类头模式，仍要求 `.export-venv`、本地官方YOLO26n起点、离线设置和独立输出目录。预定小规模参数为640输入、batch4、freeze10、AdamW、lr0 0.0002、12轮、MPS FP32、workers0、seed20260911。训练后导出静态FP32 ONNX。`scripts/evaluate_scene_model.py --class-name key` 会在CPU上检查 `[1,3,640,640] -> [1,300,6]`、ONNX元数据中的单类映射、PyTorch one-to-one分支与ONNX逐图一致性，并保存逐帧预测和耗时；不会加载正式三类模型的二次杯子复核链路。

开发评估固定 confidence 0.35、IoU 0.5，不根据holdout调参。按整段val分别报告正例召回、负例误报和逐帧预测；若开发集明显漏检，只能回到development视频补选并生成新轮次，不能读取holdout帮助选样。

## 当前限制

这只是固定机位、一个钥匙实例、三个含钥匙视频的小规模可行性试验。val正例全部为画面边缘截断姿态，独立性只达到整片分组而非新日期或新实例。任何训练指标或开发结果都不能单独证明产品达标，也不能据此替换正式模型。最终仍需冻结holdout一次性评估和真实固定摄像头事件验证。

## 实际结果

首次r02候选使用12轮、lr0 0.0002，共90.7秒。Ultralytics开发统计为R 0.2、mAP50 0.0000863；固定0.35阈值下train和val均无输出。进一步以0.001仅诊断分数分布，所有图最高分都约0.0128—0.0135，证明新单类头尚未学会置信度，而不是临界阈值问题；没有为结果降低正式阈值。

第二候选据此增加为60轮、lr0 0.001，其他主要参数保持不变，CPU训练和导出共409秒。Ultralytics按全阈值曲线给出val R 1.0、mAP50 0.995，但这不代表产品阈值通过。独立ONNX评估固定confidence 0.35、IoU 0.5后：train为1 TP、0 FP、5 FN，召回0.167；val为0 TP、0 FP、5 FN，召回0。唯一0.35以上输出是train中`23-02-14` 4秒的钥匙，置信度0.426。30张图的PyTorch one-to-one分支与ONNX输出一致性通过；ONNX CPU中位约68毫秒，p95约85毫秒。

60轮候选PT SHA-256为`5e51b5211f07affb06d1628c63a48d3c2d797fbb3223574ad20973bda05c00ee`，ONNX SHA-256为`2fae520a33637b21428009d3559fb589fc888b881793900a0aac905dbf922914`。完整私有产物在`harness/artifacts/keys-20260911-r01/runs-r03/`，独立评估在`evaluation-r03.json`。这些文件被Git忽略。

固定门失败不能仅归因于样本不足。对r03 ONNX输出在低阈值下做离线诊断（只观察分数，不改变产品0.35门槛）后，11个GT的最高置信匹配框全部达到IoU 0.5，IoU为0.761—0.912；每个GT还有7—15个IoU 0.5以上候选。模型已经学到定位，但分类/目标置信度系统性偏低。

## r04预声明

r04在训练前冻结增加4个同视频清晰正例的数据版本：1秒与13秒补充已有位置，18秒与19秒补充画面左侧、底边截断的位置。新数据仍按整片分组，不能把这些近邻帧称为独立场景。该轮同时改变了数据、学习率、轮数和训练设备，因此属于多项实验，不作单变量因果解释。训练从官方预训练权重开始，固定MPS、100轮、lr0 0.01；batch4、640输入、freeze10、AdamW、mosaic 0.2、close-mosaic 5、warmup 1、warmup bias 0.01、seed 20260911和FP32保持r03设置。

部署候选选择规则在训练前固定：分别对Ultralytics保存的best与last导出并以confidence 0.35、IoU 0.5评估完整development train/val；先比较val recall，再比较val precision，仍相同时比较train recall。跨阈值mAP不参与选择。若两者固定门均未达到可用结果，保留失败证据并停止继续盲训。

## r04结果

r04数据指纹为`e8cfd1d75de46e45ecb07411a7957fe778bbb5d2397651a56a070dd988cb2747`，共34帧：train 18、val 16；train含10个正例、val含5个正例。4个新增正例均来自`23-01-33`同一段视频。MPS训练与best导出耗时925.9秒。训练中分类loss从23.59降至1.85，最低1.65（第92轮）；box loss从1.20到1.86并明显波动。val分类loss第14轮曾异常升至982.57，末期降至1.81；mAP50第40轮达到0.995，mAP50-95第53轮最高0.464，末轮分别为0.711和0.223。

固定0.35门下，best在train为0 TP、0 FP、10 FN，在val为0 TP、0 FP、5 FN。best的PyTorch和ONNX在34帧上都为空输出，逐帧内容一致，但一致性工具按设计要求至少一个非空对，因此总体标记为失败。last在train为6 TP、4 FP、4 FN，precision 0.60、recall 0.60；4个FP来自两组同一目标的重复框。last在val仍为0 TP、0 FP、5 FN。last的PyTorch/ONNX对照34/34通过；ONNX CPU中位耗时train 71.1毫秒、val 66.6毫秒，p95分别102.3和79.8毫秒。

按预声明规则，best与last的val recall同为0且precision均无定义，再以train recall比较，选择last作为两者中较优者。但它没有检出任何整片分组开发val正例，整体r04仍判定失败，不接入产品、不进入holdout验收，也不继续盲训。该轮同时改变数据、学习率、轮数和设备，不能把变化归于某一个因素。可提交的汇总证据在`harness/evaluations/keys-20260911-r04.json`，私人逐帧预测保存在忽略目录中的`evaluation-r04-best.json`和`evaluation-r04-last.json`。
